## Part 1: Plain HTML Adaptation

Implementing a Tailwind-first system without a JavaScript framework or static site generator requires replacing component logic with standardized HTML patterns and utilizing the standalone Tailwind CLI.

### 1. Build Pipeline (Tailwind CLI)

Without Vite, Webpack, or a framework server, the build process relies entirely on the Tailwind CLI.

* Development: `npx tailwindcss -i ./src/input.css -o ./public/output.css --watch`
* Production: Appending `--minify` to the CLI command strips unused CSS and compresses the output.
* No `npm` requirement (Optional): Tailwind offers a standalone executable binary, allowing developers to compile the CSS entirely without Node.js installed on the system.

### 2. The "Component" Strategy (HTML Snippets)

Because Plain HTML lacks a templating engine (like JSX or Vue), you cannot import a `<Callout>` or `<Navbar>`. The architecture shifts from component imports to HTML snippets.

* Structural Snippets: A callout is defined by standardizing a block of HTML and its utility classes. Authors copy-paste these blocks or use editor snippets (e.g., VS Code snippets).
```html
<!-- Callout Snippet -->
<div class="bg-blue-100 dark:bg-blue-900/30 text-blue-800 dark:text-blue-200 rounded-xl p-4 flex items-start gap-3">
  <svg class="w-5 h-5 shrink-0">...</svg>
  <div>
    <p class="font-semibold mb-1">Note</p>
    <p class="text-sm">Plain HTML content goes here.</p>
  </div>
</div>

```



```

### 3. Dark Mode & Interactivity
Without React state or Vue reactivity, interactivity relies on lightweight, vanilla JavaScript injected directly into the HTML `<head>` or before the closing `</body>` tag.
* Dark Mode Script: A simple inline script checks `localStorage` and `window.matchMedia` on load to append the `.dark` class to the `<html>` element, allowing Tailwind's `dark:` variants to activate without FOUC (Flash of Unstyled Content).
* Search / Tabs: Tab switching and offline search (via a tool like FlexSearch) are handled via vanilla DOM manipulation (`document.getElementById` and `.classList.toggle`).

### 4. Directory Structure
```text
/public
  index.html
  docs.html
  /css
    output.css (Generated by Tailwind)
  /js
    theme-toggle.js
/src
  input.css (Contains @tailwind directives and CSS variables)
tailwind.config.js

```

## Part 2: Slidev Adaptation

Slidev is a Markdown-based presentation framework powered by Vite, Vue, and UnoCSS (an ultra-fast atomic CSS engine that is 100% compatible with Tailwind utility classes). Adapting this architecture for Slidev shifts the focus from continuous scrolling pages to paginated, fixed-aspect-ratio slides.

### 1. Build Pipeline & Styling Engine

Slidev natively supports Tailwind utility classes via the UnoCSS Vite plugin.

* Zero Config CSS: You do not need a `tailwind.config.js`. You can write standard Tailwind utilities directly in your Slidev Markdown files, and the engine generates the CSS on the fly.
* Typography: Slidev handles baseline typography scaling automatically based on the presentation window size, replacing the need for the `@tailwindcss/typography` plugin's `prose` class.

### 2. Slide Layouts (Vue Components)

Instead of standard page layouts (`DocLayout`), Slidev uses Slide Layouts. These are Vue components placed in the `/layouts` directory that dictate how a specific slide renders using Tailwind grid utilities.

```html
<!-- layouts/two-cols.vue -->
<template>
  <div class="slidev-layout two-cols grid grid-cols-2 gap-8 h-full">
    <div class="col-left">
      <slot name="default" /> <!-- Left side content -->
    </div>
    <div class="col-right">
      <slot name="right" />   <!-- Right side content -->
    </div>
  </div>
</template>

```

### 3. Markdown and Vue Integration

Slidev parses Markdown but treats it as a Vue template. This allows the Tailwind-first component architecture to shine identically to MDX.

* Using Components: You can place a Vue component (`Callout.vue`) in the `/components` folder, and Slidev automatically auto-imports it. You simply drop `<Callout>` into your Markdown slide.
* Utility-First Markdown: You can apply Tailwind classes directly to Markdown elements using Slidev's custom syntax.

```markdown
---
layout: two-cols
---

# Left Column

This is standard markdown.

::right::

# Right Column

<Callout type="warning">
  This is a Vue component styled with Tailwind utilities!
</Callout>

<!-- Applying Tailwind directly to a paragraph -->
<p class="text-primary-500 font-bold mt-8">
  Highlighted text.
</p>

```

### 4. Directory Structure

```text
slides.md          (The core content file, separated by ---)
/components
  Callout.vue      (Tailwind-styled Vue components)
  Tabs.vue
/layouts
  cover.vue        (Custom slide layouts utilizing Tailwind Grid/Flex)
  two-cols.vue
/styles
  index.css        (Custom CSS variables and global theme overrides)

```
